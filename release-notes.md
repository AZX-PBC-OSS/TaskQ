## [0.3.0](https://github.com/AZX-PBC-OSS/TaskQ/compare/v0.2.2...v0.3.0) (2026-09-26)


###   BREAKING CHANGES

* queue and actor names are bounded at 255 characters: enqueueing to a queue name longer than 255 characters or declaring an actor name longer than 255 characters now raises ValueError at the chokepoint (the queue at enqueue, the actor at @actor registration), where on previous releases both were accepted and later failed the jobs INSERT with an opaque btree index-size error.
* **sso:** logout is now a POST requiring the session-bound CSRF token; GET /logout answers 405 and a POST without the token answers 403, so scripts that ended an SSO session by fetching GET /admin/logout must switch to the POST
* heartbeat_timeout is now enforced by the leader's reclaim sweep: a running job whose holder stays silent past the job's heartbeat_timeout is crash-reclaimed (the reclaim event carries cause='heartbeat_timeout') even while the global TASKQ_LOCK_LEASE is still valid; the value was previously stored and ignored. Enqueue refuses only a non-positive value: heartbeat_timeout <= 0 raises ValueError naming the parameter, and a healthy positive value is accepted exactly as before. Size it at >= 2x the fleet's TASKQ_HEARTBEAT_INTERVAL.
* snoozes and admission denials no longer raise jobs.max_attempts and no longer write job_attempts/job_events rows: read the job row's snooze_count / rate_limit_blocked_count counters and the OTEL denial counters instead. An admission denial has HTTP-429 semantics: the actor never ran, so the denial consumes no retry budget, writes no per-denial rows, and never by itself terminally fails the job; a denied job is rescheduled with backoff until capacity frees or its schedule_to_close deadline expires, which fails it through the ordinary deadline path. A Snooze or a non-consuming RetryAfter refunds the dispatch claim's attempt increment, so honouring an unready downstream is unbounded and budget-free.
* retry_job (the operator re-run) no longer resets attempt to 0: the row keeps its attempt and max_attempts rises to GREATEST(max_attempts, attempt + 1), capped at the smallint bound 32767 and refused at the bound, so an exhausted 3/3 job retries as 3/4 (one fresh execution, not a full new budget) and a mid-budget 1/5 job keeps its remaining budget; every terminal status is now a valid retry source (succeeded and abandoned included) while running stays excluded.
* BatchHandle.wait_for_batch() now defaults to on_empty="error": a batch_id with zero jobs and no batches row raises EmptyBatchError where it previously returned an empty BatchCompletionStatus silently; pass on_empty="ok" to keep the silent-return behaviour.
* the sub_enqueue_re_enqueue_error and sub_enqueue_flush_error events now carry error_class + error_message instead of the single message field, matching the error_class/error_message convention of every other error event: log pipelines querying fields.message on these two events must switch to error_message.
* a cron schedule configured with dst_strategy 'firstof' or 'allof' changes firing behaviour on upgrade: on an autumn fall-back night an 'allof' schedule now enqueues two jobs for the repeated local hour where it previously enqueued one; audit for non-skip schedules before rolling out and make sure their actors are idempotent.
* the default unique_states for unique_for is now (pending, scheduled, running, succeeded), previously (pending, scheduled, running), so a re-delivered webhook or a double-clicked button inside a still-open window no longer runs the work a second time; actors that want the old block-only-concurrent-execution behaviour must pass unique_states explicitly, and a dedup onto an already-finished job now logs enqueue_deduplicated at WARN naming the matched status.
* enqueue and enqueue_batch with an idempotency_key that matches an existing job of a different actor now raise IdempotencyKeyActorMismatchError (naming both actors, the key, the scope and the existing job id) with nothing enqueued, where the first actor's job handle was previously returned with was_existing=True; the batch tier withdraws the whole batch, and a cross-actor pair in enqueue_batch_fast aborts the whole COPY the same way. Namespace keys per actor or use per-actor idempotency_scope values.
* enqueue_batch, enqueue_batch_fast and the chunked arm of enqueue_batch_streaming now admit the within-cap actors' items and refuse only the over-cap actors' items as whole groups, raising BatchMaxPendingExceededError after the admitted items are stored: previously one capped actor aborted the whole call with MaxPendingExceededError and nothing was enqueued; except MaxPendingExceededError no longer catches bulk cap refusals (the new error is deliberately not its subclass), and a handler that blindly retries on BackpressureError now duplicates the admitted items; consult admitted_count / refused_indices and retry only the refused items.
* the taskq.cron.consecutive_failures gauge is now labeled by the schedule row's actor (bounded to the first 100 distinct names a worker process sees; later names collapse onto the fixed _other_ value) instead of the per-schedule UUID: dashboards and alert rules grouping by schedule_id lose their series on upgrade; per-schedule attribution lives on the cron fired / cron fire failed log lines and the cron fire span's taskq.cron_schedule_id attribute, and cron_schedules.consecutive_failures remains the authoritative per-schedule record.
* the job state-transition structured-log event is now emitted as state-change from every backend alike: it shipped as state_change in v0.2.2; nothing fails, but saved searches, dashboard panels and alert rules matching the old name simply stop matching.
* the queue-name, tag and keyed rate-limit key regexes are now anchored \A...\Z instead of ^...$: Python's $ also matches immediately before a trailing newline, so values like "default\n" or "mytag\n" that satisfied the old patterns are now rejected with ValueError; guard call sites that derive names from shell command substitution or file reads.
* the public actor-config import paths moved: taskq.worker.actor_config is now taskq.actor_config and taskq.worker.actor_config_ops is now taskq.actor_config_ops, so importers of the old paths must update (the state-machine constants move, taskq.backend.statemachine to taskq.backend, is not breaking: the old path still imports).
* taskq.validate_actor_payload's third parameter is renamed actor_name to actor (the positional form is unaffected, the keyword form must change), and the export now resolves to the single sanitized implementation: the exception message no longer contains payload values (log pipelines and admin tooling that parse error_message must update), and PayloadValidationError.validation_errors entries no longer carry input or url keys.
* new bounds and charset guards now reject input that was previously accepted, each as a clean error: set_queue_max_concurrent refuses 0 (>= 1 or None), enqueue_batch refuses an empty item list, BatchFilter.limit is capped at 500, admin job-list status values must be in the closed status set, JobFilter and ScheduleCreateArgs text fields reject NUL bytes, ScheduleCreateArgs.dst_strategy must be a known strategy, and the batch public API's schema parameter is validated against the schema-identifier regex before interpolation (a SQL-injection surface).
* WorkerSettings gained load-time validators: schema_name longer than 63 characters, a non-UUID workgroup_instance, a NUL in worker_label, or a queue name outside the queue-name charset now fail the settings load instead of producing an opaque mid-startup failure, and the cross-field invariants raise dotenvmodel's ValidationError / MultipleValidationErrors rather than ValueError, so callers that catch ValueError around WorkerSettings.load must catch DotEnvModelError (the common base) instead.
* taskq._json.dumps() now requires str dict keys: non-str keys raise TypeError instead of being silently coerced; stringify keys before enqueue (Pydantic-validated payloads are unaffected: dict[str, ...] model fields already reject non-str keys at validation).
* allow_cookieless_fallback now defaults to false; a deployment that relies on the cookie-less ACS callback fallback must set it explicitly on the SAML config
* pools built from a DSN send no per-connection GUCs in the startup packet; move server_settings such as jit=off into ALTER ROLE or the DSN's options=
* **admin:** GET /admin/jobs/sse/live is removed. Consumers of the live job feed use GET /admin/sse/jobs, the route the jobs page itself uses, which carries the same events under the same cap.
* taskq._json.dumps() now requires str dict keys  non-str keys raise TypeError (previously silently coerced); stringify keys before enqueue.
* passing heartbeat_timeout to any enqueue API (JobsClient.enqueue, TaskQ.enqueue, SubJobEnqueuer.enqueue) now raises ValueError naming the parameter. It was previously accepted, stored, and read by nothing  a per-job reclaim promise the library never kept; reclamation is governed by the global TASKQ_LOCK_LEASE.
* page every job-list ordering, by ordering id with the sort column
* **obs:** drop identity values from metric dimensions before they throttle ingestion
* **web:** admin pages could be framed and UI-redressed; CSRF cookie lost Secure behind TLS termination
* **consumer:** validate payload before acquire; pass the validated model
* **api:** export the sanitized validate_actor_payload from the public API
* **ratelimit:** refund the store that actually paid, not the configured one
* EnqueueArgs.scheduled_at is now None-able and no longer defaults to a client-side now() stamp  "immediate" enqueue passes None and the server stamps it; Backend implementations that require a non-None datetime now fail loudly. The raw schedule_to_close datetime form is deprecated in favor of schedule_to_close_interval. Rate-limit Redis scripts derive time from redis.call('TIME') (caller-supplied now ARGV removed). Full suite 5122 passed; pyright, ruff, mkdocs, uv lock --check all clean.
* **deps:** dotenvmodel 0.6.3 -> 1.0.0. Real environment variables now take precedence over .env file values (previously .env files overwrote os.environ); set DOTENV_OVERRIDE=true or pass override=True to restore files-beat-env-vars. TaskQSettings.load() no longer mutates os.environ. An invalid TaskQ(redis_url=...) now raises TypeCoercionError at open() (previously a late ValueError from redis-py) and an empty or whitespace redis_url raises ValueError at construction. AppSettings subclasses whose string field defaults contain ${VAR} now interpolate them at load time (unset references resolve to "").
* **testing:** make_integration_settings/make_integration_settings_dict no longer default to the deterministic per-worker schema tq_<worker>; the default is a unique per-call name (explicit schema_name= unchanged).
* **consumer:** always pass validated_payload to acquire_for_actor
* **ratelimit:** make payload_type required, add .typed() to both keyed refs
* **actor-config:** sync_actor_config (and therefore worker startup) no longer raises ActorConfigDriftList for a max_concurrent, max_pending, or result_ttl mismatch between the registered actor and the stored row  only queue and metadata mismatches still raise. ActorConfigDriftError.field narrows from Literal["max_concurrent", "max_pending", "queue", "result_ttl", "metadata"] to Literal["queue", "metadata"]. --force-update-actor-config / TASKQ_FORCE_UPDATE_ACTOR_CONFIG no longer affect capacity fields at all  they are unconditionally preserved by the UPSERT once a row exists. Consumers who relied on a differing @actor(...) literal fatally refusing worker startup for capacity fields must now use `taskq actor-config set` to change stored capacity going forward; a stale literal is only logged.
